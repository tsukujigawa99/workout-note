# 仕様書 06：記録写真（写真にその日の記録を載せる）

- 作成: PM（2026-10-08）　／　宛先: 開発担当・テスト担当
- 版: v1.2.0 で追加
- 目的: 依頼者が使っていた筋トレMEMOの「写真に記録を載せる」機能の代替。ジムで撮った写真の上に、その日の種目・セット（重量×回数）・推定RMを白いカードで重ね、1枚の画像として保存・共有できる。
- 見本: 依頼者提供のサンプル画像（PM が開発・テスト担当へパスを渡す）。縦写真の右側に「日付（曜日）今日」見出し＋種目ごとの白半透明カード。

## 1. 方針（守ること）

- **写真はアプリの外に出さない・残さない**。canvas でその場で合成するだけ。Firestore / localStorage には一切保存しない。ネットワーク通信もしない。
- 既存の設計原則はそのまま（保存先に触らない機能なので同期ロジックは変更しない）。
- ビルドなし・外部ライブラリなし。相対パス。`mock/mock.html` の見た目は変えない（ホームにボタンを1つ足すだけ）。
- 合成画像の配色は **アプリのテーマ（赤/黒）とは独立**。見本どおり「白カード」を基本にし、「黒カード」を選べる。
- iPhone Safari（ホーム画面アプリ含む）と PC Chrome/Edge で動くこと。

## 2. 入口（ホーム画面）

- 選択日に有効セットのある種目が 1 つ以上ある時だけ、記録カード一覧（`.records`）の直下・メモ欄の上に次を表示:
  `<div class="photo-row"><button class="btn sm ghost" data-act="photo">(カメラアイコン) 写真に記録を載せる</button></div>`
- 同じ画面内に隠しファイル入力を置く: `<input type="file" id="photo-in" accept="image/*" hidden aria-hidden="true">`（常に出力してよい）。
- `photo` アクション: クリックハンドラ内で**同期的に** `$('#photo-in').click()`（iOS はユーザー操作の中でないとピッカーが開かない）。
- `change`（home.js に `onChange(t)` を追加）: `t.id === 'photo-in'` で `t.files[0]` があれば `openPhotoSheet(file, S.date)` を呼び、直後に `t.value = ''`（同じ写真を続けて選べるように）。
- アイコン: `ui.js` の `IC` に `camera` を追加（24px 線画。例: `M4 8h3l2-3h6l2 3h3v11H4zM12 17a4 4 0 100-8 4 4 0 000 8z`）。

## 3. シート「記録写真」（`sheets.js` の `sheet()` を使う）

構成（上から）:
1. プレビュー: 合成結果の `<canvas class="photo-prev">`（CSS: `display:block;max-width:100%;max-height:55vh;width:auto;height:auto;margin:0 auto;border-radius:12px;background:var(--sunk)`）。読み込み中は `<div class="empty" role="status">写真を読み込んでいます…</div>` を同じ場所に出す。
2. オプション（2列グリッド `.photo-opts`、各列は `<div><span class="lbl">位置</span><div class="seg">…</div></div>`、既存 `.seg` のスタイルを流用）:
   - 位置: `左` / `右`（既定 右）。`data-act="photoPos" data-arg="left|right"`
   - カード: `白` / `黒`（既定 白）。`data-act="photoStyle" data-arg="white|black"`
   - 切替のたびに再合成してプレビューを差し替える（連打しても最後の設定で描けばよい。描画中フラグで多重描画を避ける）。
3. 注記 `<p class="note">写真はこの端末の中だけで合成します。アプリには保存されず、どこにも送信されません。</p>`
4. ボタン行 `.btnrow`: `別の写真を選ぶ`（`data-act="photoPick"` → `$('#photo-in').click()`）／`保存・共有`（`data-act="photoShare"`、class `btn pri`。合成が終わるまで `disabled`）。
5. iPhone 向けの補足 `<p class="note">iPhone では共有画面の「画像を保存」で写真に保存できます。</p>`（`navigator.share` が使える環境でだけ表示）

### 保存・共有の動き

- 合成が終わるたびに `canvas.toBlob(blob => …, 'image/jpeg', 0.92)` を**先に**実行し、`File`（名前 `WorkOutNote_YYYY-MM-DD.jpg`、type `image/jpeg`）を状態に保持しておく。ボタン押下時に非同期処理を挟むと iOS で `navigator.share` が「ユーザー操作外」と判定されて失敗するため。
- `photoShare`:
  1. `navigator.canShare && navigator.canShare({ files: [file] })` なら `navigator.share({ files: [file], title: 'WorkOut Note ' + 日付 })`。`AbortError`（ユーザーがキャンセル）は無視。それ以外の失敗は 2 へフォールバック。
  2. それ以外: `<a download>` + `URL.createObjectURL(blob)` でダウンロード。表示は `toast('画像を保存しました')`。`revokeObjectURL` は 1 秒後。
- シートを閉じたら（×／背景／戻る／別画面へ遷移）`ImageBitmap.close()`・objectURL の解放・保持している File/blob の破棄を行う。`sheet()` が中身を消すだけなので、`photo` 側で「閉じられたか」は `sheetOpen()` か自前の要素存在チェックで判定してよい。

### 失敗時

- 画像をデコードできない: `toast('この写真は読み込めませんでした。JPEG か PNG の写真をお試しください')` してシートを閉じる。
- ファイルが画像でない（`file.type` が `image/` で始まらず、拡張子も jpg/jpeg/png/webp/heic/heif でない）: 同上。
- 合成に必要な Web フォントが取れない（オフライン等）: システムフォントで描く（失敗にしない）。

## 4. 合成の仕様（`app/js/photo.js`、純粋計算は `app/js/photo-layout.js`）

### 4.1 画像の読み込み・サイズ

- `createImageBitmap(file, { imageOrientation: 'from-image' })` を試し、未対応／失敗なら `Image` + objectURL で読む（iPhone 写真の EXIF 回転を正しく扱う。縦で撮った写真が横倒しにならないこと）。
- 出力サイズ: 長辺を **最大 1600px** に縮小（拡大はしない）。縦横比は維持。`canvas.width/height` はこの値。
- 写真を `drawImage` で全面に描く。

### 4.2 寸法の基準

- `u = min(W, H) / 1080`（W,H は canvas サイズ）。以下の px はすべて `× u`。
- パネル幅 `P = clamp(round(0.46 × W), 400u, 560u)`。外側余白 `m = 28u`。
- パネル x: 右なら `W − m − P`、左なら `m`。見出しの開始 y: `round(0.075 × H)`。

### 4.3 見出し

- 1行目: 日付 `2026/10/08` を **Oswald 600 / 64px**、続けて半角スペース＋`(木) 今日`（今日でなければ `(木)` のみ）を **Noto Sans JP 500 / 26px**。ベースラインを揃える。
- 色: 白 `#FFFFFF`。影 `shadowColor rgba(0,0,0,.55) / shadowBlur 10 / shadowOffsetY 2`。
- 見出しの下に太さ `2px` の白線（幅 P、見出しベースラインの 14px 下）。線の下 22px からカード開始。

### 4.4 カード（種目ごと）

- 対象: その日の `items` のうち `validSets(it).length > 0` のもの、保存順。セットは有効セットのみ、セットの **メモは載せない**。
- 白: 背景 `rgba(255,255,255,.88)`、文字 `#2B2021`、補助文字 `#706364`。黒: 背景 `rgba(20,16,17,.80)`、文字 `#F1EBEB`、補助文字 `#9C8F8F`。
- 角丸 `16px`、内側余白 上下 `18px` 左右 `20px`、カード間 `14px`。
- 見出し行（高さ 36px）: 部位色の丸（半径 7px、`exColor(it.ex)` が CSS 変数文字列の時は補助文字色で描く）→ 10px → 種目名 **Noto Sans JP 700 / 26px**（`exName(it.ex)`。はみ出す場合は末尾を `…` で切る）。右端に `RM : 57.50kg` を **Oswald 500 / 20px** 補助文字色で右揃え（`f2(itemRM(it)) + 'kg'`）。
- セット行（1 行 40px、Oswald 400 / 26px、`tabular` 相当で桁揃え）:
  - 列: セット番号（左端 +12px、左揃え）／重量 `45.0 kg`（左端 +150px を右端にして右揃え。`fw(s.w)`、空は 0 扱い＝`setW`）／`×`（左端 +170px、補助文字色）／`10 reps`（左端 +196px、左揃え）。
  - `assist` のセットは `reps` の後ろに ` 補助` を Noto Sans JP 400 / 18px 補助文字色で付ける。
- 「補助文字色」= 上記の白/黒それぞれの 2 色目。

### 4.5 収まらない時（`photo-layout.js` の純粋関数で決める）

- 使える高さ `avail = H − カード開始 y − m`。
- 必要高さ `need = Σ(カード高) + 14px × (枚数 − 1)`、カード高 `= 18×2 + 36 + 40 × セット数`（すべて × u × scale）。
- 手順: `scale = 1.0` から `0.05` 刻みで `0.6` まで下げて、`need ≤ avail` になる最初の scale を採用。`0.6` でも収まらなければ、`0.6` のまま**末尾から種目を外して**収まる最大枚数にし、カード群の下に `他 N 種目` を白文字（Noto Sans JP 500 / 22px、影付き）で描く。
- scale はカード内の文字サイズ・行高・余白すべてに掛ける（パネル幅・見出しは変えない）。
- 純粋関数の形（テスト対象）:
  - `fitPlan(setCounts: number[], availPx: number, u: number) → { scale: number, count: number }`（count = 描く種目数）
  - `photoText(day, dateKey, todayKey, exName, exColor) → { date: '2026/10/08', sub: '(木) 今日', items: [{ name, color, rm: '57.50', sets: [{ n: 1, w: '45.0', r: 10, assist: false }] }] }`（`WD`／`slash`／`validSets`／`itemRM`／`f2`／`fw`／`setW` を使う。`day` が無い・種目が無いなら `items: []`）

### 4.6 フォント

- 描画前に `document.fonts.load()` で `600 64px Oswald`、`500 20px Oswald`、`400 26px Oswald`、`700 26px "Noto Sans JP"`、`500 26px "Noto Sans JP"`、`400 18px "Noto Sans JP"` を**実際に描く文字列（種目名を連結したもの等）を渡して**読み込む（Google Fonts は文字単位の分割配信のため、日本語文字を渡さないと和文が読み込まれない）。
- 全体を `Promise.race` で **2 秒**で打ち切り、未読込ならそのまま描く（フォールバックは CSS と同じ `"Oswald","Arial Narrow","Noto Sans JP",sans-serif` / `"Noto Sans JP","Hiragino Sans","Yu Gothic UI","Meiryo",sans-serif`）。
- 文字の描画は `ctx.textBaseline = 'alphabetic'` で統一し、行の y はベースライン基準で計算する。

## 6. 受け入れ基準（テスト担当のチェック項目）

1. `tests/test.html` が全件 PASS（既存 150 件＋新規）。
2. ホーム: 記録のない日はボタンが出ない。記録のある日は記録カードの下に出る。320px 幅でボタンが折り返しても崩れない。
3. ボタン → ファイル選択 → シートが開き、数秒以内にプレビューが出る（縦写真・横写真・正方形の 3 種で確認。長辺 1600px 以下になっている）。
4. 合成結果が見本に近い: 右側に白カード、日付見出し、種目名・RM・セット行の桁揃え。左／右、白／黒の切替が効く。
5. 種目が多い日（例: 8 種目×4 セット）でカードが縮小され、それでも収まらない時は「他 N 種目」が出て写真からはみ出さない。
6. 保存・共有: PC Chrome ではダウンロード（または共有）される。ファイル名 `WorkOutNote_YYYY-MM-DD.jpg`。
7. シートを閉じて再度開ける。「別の写真を選ぶ」で差し替えられる。× ／ 背景タップ／ブラウザバックで閉じる（既存シートと同じ挙動）。
8. 画像以外のファイル（テキスト等）を選ぶとトーストで断られ、アプリは壊れない。
9. 同期に影響しない: 合成後も `localStorage` の `won-days` 等が変化しない。写真データがどこにも残らない。
10. 赤テーマ・黒テーマ両方でシートの見た目が崩れない。
11. 自動テストで確認できない iPhone 実機（ホーム画面アプリからカメラ起動・「画像を保存」）は依頼者確認項目として報告に残す。

## 7. 追補（v1.2.1）: 写真の左右反転

- 背景: iPhone の内カメラ（自撮り）で撮った写真は、撮影時に画面で見た向きと左右が逆に保存される。依頼者より「反転して元に戻せるように」との要望（2026-10-09）。
- シートのオプションに 3 列目「反転」を追加: `なし` / `あり`（既定 なし）。`data-act="photoFlip" data-arg="off|on"`。`.photo-opts` は 3 列グリッド（`grid-template-columns:repeat(3,1fr)`）。320px 幅でも各ボタンの文言が 1 行に収まること。
- 「あり」の時は**写真だけ**を左右反転して描く（`ctx.translate(W,0); ctx.scale(-1,1)` で drawImage。その後 restore）。見出し・カードの文字は反転しない。位置（左／右）の指定は反転後の画像に対してそのまま効く（右を選べば右に出る）。
- 切替のたびに再合成（既存の位置・カード切替と同じ流れ。保存用 File も作り直す）。
- 版: `APP_VERSION` と `CACHE_VERSION` を 1.2.1 に。tests/test.html のバージョン検査も更新。
- 受け入れ: 反転 あり→なし→あり で写真が左右入れ替わり、文字は常に正しい向き。3 列が 320px で崩れない。保存される画像にも反転が反映される。
