## 1. 技術制約

- **ビルドなし**。Node.js は無い。素の HTML / CSS / JavaScript（ES Modules、`<script type="module">`）。外部ライブラリなし（フェーズ2のFirebase SDKのみ例外）。
- 配信は静的ファイルのみ。**相対パス**で参照（GitHub Pages のサブパス `/<repo>/` 配下で動くこと）。
- ローカル確認: `python -m http.server 8765 --directory C:/AgDev/claude/kintore-memo/app`（`.claude/launch.json` に `workout-note` として登録済み）。
- 対応: iPhone Safari（ホーム画面追加のスタンドアロン含む）、PC Chrome/Edge。
- Python 3.13＋Pillow は利用可（アイコンPNG生成などに使ってよい）。

## 3. データモデル（フェーズ2のFirestore構造と同形にする）

```
days     : { "YYYY-MM-DD": { memo: string, items: [ { ex: exId, sets: [ { w: number|null, r: number|null, memo: string, assist: boolean } ] } ], updatedAt: number } }
body     : { "YYYY-MM-DD": { w?: number, f?: number, updatedAt: number } }
master   : { parts: [ { id, name, color, hidden? } ], exercises: [ { id, part, name, hidden? } ], updatedAt }   ※配列順＝表示順
settings : { step: 2.5, timerSec: 90, updatedAt }
```

- フェーズ2では `users/{uid}/days/{date}`、`users/{uid}/body/{date}`、`users/{uid}/meta/master`、`users/{uid}/meta/settings` に対応。
- **種目IDは不変**（名称変更しても過去記録が繋がる）。新規IDは衝突しない文字列（例: `x` + 時刻36進 + 乱数）。
- 種目・部位の「削除」は `hidden: true`（過去記録は残す）。hidden の種目も履歴・ホームには名前を表示。
- テーマ（赤/黒）は同期対象外。端末ごとに `localStorage['won-skin']`。

### store インターフェース（同期読み・非同期書き）

```js
await store.init()                 // キャッシュをメモリに展開
store.onChange(cb)                 // データ変更時（将来はリモート変更も）に再描画用コールバック
store.days()  / store.day(k)       / store.saveDay(k, day)   // itemsが空かつmemo空なら削除
store.bodies()/ store.body(k)      / store.saveBody(k, rec)  // w,fとも空なら削除
store.master()/ store.saveMaster(m)
store.settings()/ store.saveSettings(s)
```
LocalAdapter のキー: `won-days` `won-body` `won-master` `won-settings`（JSON）。書き込み失敗（容量・プライベートモード）は try/catch し、トーストで通知。

## 4. 計算ルール（calc.js）

- 有効セット: `r > 0`。`w` が空なら 0kg 扱い。
- 推定1RM = `w × (1 + r / 40)`。表示は小数2桁（履歴カードのMAXは小数1桁）。検算値: 35×15→48.13、35×20→52.50、58×33→105.85。
- ボリューム = Σ(w × r)。トン表示は kg÷1000 を小数2桁。
- 7日間 = 今日を含む直近7日。週別バー = 今日起点で7日ずつ6本（今週, 1〜5週前）。28日間 = 直近28日。総合計 = 全期間。
- 乗り物換算: 乗用車 1,500kg／バス 15,000kg／旅客機 350,000kg、小数1桁。
- MONTHLY ARCHIVE = 表示中の月の「有効セットが1つ以上ある日」の数。TOTAL = 全期間の同日数。
- 「今日」は描画のたびに取得（日付またぎ対応）。日付キーは**ローカル時刻**で生成（`toISOString` 禁止＝UTCずれ防止）。

## 5. 画面仕様（mock.html からの差分・補足のみ）

共通:
- サンプルデータは入れない。初回は空状態＋初期マスタ（mock の PARTS/EX と同じ部位・種目。`base` は不要）。
- ヘッダの名称は「WorkOut Note」（「仮称」表記・モック注記は削除）。
- ルーティングは **hash ベース**（`#/home` `#/pick` `#/entry/<exId>` `#/history/<exId>` `#/analysis` `#/body` `#/settings` `#/master`）。ブラウザの戻る／iPhoneのスワイプ戻るで前画面に戻れること。選択中の日付は状態として保持。
- 入力は**即時自動保存**（保存ボタン不要。「記録して戻る」はホームへ戻るだけ）。入力中に再描画でフォーカスが飛ばないこと。
- ユーザー入力文字列は必ずエスケープして表示。
- input の font-size は 16px 以上（iOSの自動ズーム防止）。タップ領域は原則 40px 以上。

ホーム: mock どおり。カレンダーの月タイトル付近をタップ、または「今日」操作で今月・今日に戻れる導線を1つ用意。

種目選択: 非表示(hidden)の部位・種目は出さない。「新しい種目を追加」→ 種目名を入力して現在の部位に追加し、そのままセット入力へ。

セット入力:
- 開いた時点で当日の該当種目が無ければ空3セットを表示（有効セットが入るまで保存データには残さない／戻る時に空セットは除去）。
- ±ボタンの重量ステップは settings.step。重量が空で＋を押したら「前セットの重量 → 無ければ前回記録の1セット目 → 無ければ20」を入れる。回数が空で±なら10。
- 「セットを追加」は直前セットの重量を引き継ぎ、回数欄にフォーカス。
- 重量 0〜999.5、回数 0〜999 に丸める。負数・非数は無視。
- 「この種目の記録を削除」（確認あり）を画面下部に追加。
- Last Record は「選択日より前」の直近記録。コピーは重量・回数のみ（メモ・補助はコピーしない）。

タイマー（timer.js）:
- 終了時刻ベースで計測し、**画面遷移しても継続**。セット入力画面以外にいる時も終了時にトースト＋音。
- 音は Web Audio。iOS対策として START タップ時に AudioContext を生成/resume。バイブは `navigator.vibrate` があれば使用（iPhoneは非対応なので音＋画面のみ）。
- プリセット 60/90/120/180。初期値は settings.timerSec。

履歴/分析・種目履歴・体組成: mock どおり。グラフは記録2件未満なら案内文。体組成は今日以外の日付も入力できるよう日付選択（`<input type="date">`）を付ける。

設定:
- テーマ切替／重量ステップ（1, 1.25, 2.5, 5 から選択）／インターバル初期値（秒）／部位・種目の管理へ。
- 「同期の状態」「ログアウト」はフェーズ2で追加するため、フェーズ1では表示しない。
- アプリのバージョン表記。

部位・種目の管理（master）: 部位ごとに種目を一覧。種目の追加・名称変更・上下並び替え・非表示/再表示。部位も追加・名称変更・色選択（プリセット色）・並び替え・非表示。

過去の日からコピー: 直近の実施日を新しい順に30件。コピー先に既にある種目は重複追加しない。

RM計算機: mock どおり。

PC幅（960px以上）: mock と同じく 920px の中央カラム。記録カードは複数列。

## 6. PWA

- `sw.js`: インストール時にアプリシェル（index.html, css, js 全部, icons, manifest）をキャッシュ。fetch は同一オリジンGETのみ扱い、**stale-while-revalidate**。`CACHE_VERSION` を上げると旧キャッシュ削除。Google Fonts は実行時キャッシュ。SW登録は `localhost` か https の時だけ。
- アイコン: 赤地(#D23B38)に白のダンベル記号。マスカブル対応の余白。
