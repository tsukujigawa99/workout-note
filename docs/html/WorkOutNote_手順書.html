2. 初期セットアップ A：Firebase ご本人作業

記録の保管庫とログイン機能を用意します。費用は 0 円です。途中でクレジットカードの登録を求められたら、進まずに中止してください（無料の Spark プランでは不要です）。

A-1　プロジェクトを作る

  1. https://console.firebase.google.com/ を開き、iPhone でも使う個人の Google アカウントでログインします。
  2. プロジェクトを作成 → 名前 workout-note → 続行。
  3. Google アナリティクスはオフのまま プロジェクトを作成。
  4. 左下の料金プランが Spark（無料）であることを確認します。

A-2　Google ログインを有効にする

  1. 左メニュー 構築 → Authentication → 始める。
  2. ログイン方法 タブ → Google → 有効にする → サポートメールに自分のアドレスを選び 保存。

A-3　データベース（Firestore）を作る

  1. 左メニュー 構築 → Firestore Database → データベースの作成。
  2. ロケーションは asia-northeast1 (Tokyo)。後から変更できません。
  3. 本番環境モードで開始 → 作成。

A-4　ウェブアプリを登録して接続情報を得る

  1. プロジェクトの概要 → アプリを追加 → ウェブ（</>）。
  2. ニックネーム WorkOut Note。「Firebase Hosting も設定する」はチェックしない → 登録。
  3. 表示された firebaseConfig = { … } の中身を app/js/firebase-config.js に反映します（現在は設定済み）。
firebaseConfig は秘密情報ではありませんこれは「接続先の住所」で、Web アプリでは公開される前提の値です。データを守るのは Google ログインとセキュリティルール（4章）です。

3. 初期セットアップ B：GitHub ご本人作業

  1. https://github.com/ でアカウントを作成（またはログイン）します。
  2. 右上の ＋ → New repository → 名前 workout-note、Public を選んで Create repository。
    • Public にするのは、無料プランで GitHub Pages を使うためです。公開されるのはプログラムだけで、トレーニング記録は含まれません。
  3. リポジトリの URL（https://github.com/tsukujigawa99/workout-note.git）を控えます。

4. 公開前の設定 ご本人作業

4-1　Firestore のセキュリティルールを貼る

  1. Firebase コンソール → Firestore Database → 上部の ルール タブ。
  2. 表示されている内容をすべて消して下を貼り付け、公開 を押します。 
    rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}

    意味：「ログインしている本人の users/本人ID/ 以下だけ読み書きできる。それ以外はすべて拒否」。同じ内容がリポジトリの firestore.rules にもあります。

4-2　ログインを許可するサイトを追加する

  1. Firebase コンソール → Authentication → 設定 タブ → 承認済みドメイン。
  2. ドメインを追加 → tsukujigawa99.github.io を入力して追加します。localhost は最初から入っています。

4-3　初回アップロードと GitHub Pages の有効化

  1. PC のターミナル（PowerShell やコマンドプロンプト）で次を実行します。GitHub のログイン画面が開いたら、ご本人がブラウザでログインして許可します。 
    git -C C:\AgDev\claude\kintore-memo push -u origin main

    branch 'main' set up to track 'origin/main' と出れば成功です。認証情報は PC に保存され、次回からは聞かれません。

  2. GitHub のリポジトリ → Settings → 左メニュー Pages → Source を GitHub Actions にします（保存ボタンはありません）。
  3. Actions タブで「Deploy to GitHub Pages」に緑のチェックが付けば公開完了です。走っていなければ、その名前を選んで Run workflow を押します。

5. iPhone と PC で使い始める

PC

  1. Chrome か Edge で https://tsukujigawa99.github.io/workout-note/ を開き、ブックマークします。
  2. ホームの案内カードの Googleでログイン を押し、開いたウィンドウでアカウントを選びます。設定画面に自分のメールアドレスが出れば成功です。
  3. その端末に未ログインで入れた記録がある場合は、「クラウドにアップロードしますか」と聞かれます。残したい記録なら アップロード を選びます。

iPhone

ホーム画面のアプリからログインできない場合iOS のバージョンによっては、ホーム画面アプリから開く Google のログインウィンドウがうまく戻らないことがあります。表示されたメッセージ（またはスクリーンショット）を控えて開発担当へ連絡してください。別のログイン方式に切り替えて対応します。その間も Safari からは利用できます。

6. 日々の使い方

やりたいこと操作
別の日に記録するホームのカレンダーで日付をタップしてから「トレーニングを追加」。月名をタップすると今日に戻ります。
前回と同じ内容で始めるセット入力画面の Last Record にある コピー。すでに入力がある時は確認が出ます。
過去の日のメニューを丸ごと使うホームの 過去の日からコピー → 日付を選ぶ。すでにある種目は重複しません。
重量をすばやく変える重量の − ＋。1回の増減幅は 設定 →「重量の増減ステップ」で変更（1 / 1.25 / 2.5 / 5 kg）。
セットを消す・戻すゴミ箱で削除。直後に出る 元に戻す で復元できます（約5秒・直前の1件）。
補助してもらったセットに印そのセットの ✓ 補助 をタップ。
伸びを確認する下部タブ 履歴/分析 → 種目を選ぶ。推定1RM と総ボリュームのグラフ、日付ごとの記録。
体重・体脂肪を記録する下部タブ 体組成。日付を変えて過去分も入力できます。
種目を足す・名前を変える・隠す設定 →「部位・種目の管理」。削除ではなく非表示にするので、過去の記録は残ります。
RM を計算するホームの RM計算機。重量と回数から推定1RM と回数別の目安重量を表示。
赤／黒テーマを切り替えるホーム右上の ◐ ボタン。端末ごとに記憶されます。
同期の状態を見る設定 →「アカウント／同期」。送信待ちやオフラインの時だけ、ホームの上部にも小さく表示されます。
電波がない場所で使う時一度でもオンラインでログイン・同期した端末なら、機内モードでも起動して記録できます。記録は「送信待ち」として端末に貯まり、つながった時に自動で送られます。初めてログインする端末だけは、最初の読み込みが終わるまでオンラインである必要があります。

7. アプリを修正して公開し直す

  1. C:\AgDev\claude\kintore-memo\app\ 以下を修正します。見た目は css/app.css、画面は js/screens/、計算は js/calc.js です（詳しくは設計書）。

  5. GitHub の Actions タブで緑のチェックを確認します。端末ではアプリを開き直します（1回目で裏に取り込み、2回目から新しい版）。設定画面の版番号で確認できます。

8. PC のローカルで動かす・テストする

Node.js は不要です。Python の簡易サーバーで動きます。

アプリを開く

python -m http.server 8765 --directory C:/AgDev/claude/kintore-memo/app

ブラウザで http://localhost:8765/ を開きます。localhost は Firebase の承認済みドメインに最初から入っているので、ログインも試せます。公開版とは保存場所が別なので、未ログインで入れた記録は公開版には出ません。

自動テストを走らせる

python -m http.server 8766 --directory C:/AgDev/claude/kintore-memo

http://localhost:8766/tests/test.html を前面のタブで開くと自動で実行され、タブのタイトルと画面に PASS n / FAIL m が出ます（v1.1.1 時点で 150 件）。裏のタブだと完了が遅くなります。

修正が画面に出ない時Service Worker が古い控えを返していることがあります。ブラウザの開発者ツール → Application → Service Workers で Unregister、Storage で Clear site data をしてから再読み込みします（未ログインの記録も消えるので注意）。

9. 困った時は

症状考えられる原因対処
ログイン後に「権限がありません」「同期エラー」と出るFirestore のセキュリティルールが未適用、または内容が違う4-1 のルールを貼り直して「公開」。その後、設定 →「アカウント／同期」→ 再接続（自動でも数十秒おきに再試行します）。
「承認済みドメインに追加してください」と出る公開サイトのドメインが Firebase に未登録4-2 の手順で tsukujigawa99.github.io を追加。
ログインのウィンドウが開かないブラウザのポップアップブロックアドレスバーのブロック表示から、このサイトのポップアップを許可。
iPhone のホーム画面アプリでログインできないiOS のポップアップ制限5章の注意書きのとおり、メッセージを控えて連絡。当面は Safari で利用。
「クラウドの記録を読み込み中です」と出て入力できない初めてログインした端末で、最初の読み込みが終わっていない（電波が弱い）電波の良い場所で数秒待つ。上書き事故を防ぐための仕様です。
もう片方の端末に記録が出ない送信側がオフライン／別の Google アカウントでログインしている両方の端末の 設定 →「アカウント／同期」でメールアドレスと同期状態を確認。
「データの一部を読み込めませんでした（退避済み）」端末内データの破損（未ログイン時）壊れた元データは won-…-corrupt-日時 という名前で端末内に退避されています。復旧が必要なら開発担当へ。
タイマーの音が鳴らない消音モード、またはアプリが裏に回った／画面ロック中iPhone は画面を点けたまま使う。裏に回った場合は、戻った時点で通知されます。
更新したのに古い画面のまま端末の控え（キャッシュ）が残っている／版番号を上げ忘れたアプリを完全に閉じて2回開き直す。直らなければ 7章②を確認。
Actions が赤い×で失敗するPages の Source が「GitHub Actions」になっていない等4-3 の Settings → Pages を確認し、Re-run jobs。
push でログインを求められて失敗するPC に GitHub の認証情報が無いご本人がターミナルで git push を実行し、開いたブラウザでログイン。

10. データの保全と注意点

  • ログインして使うのが基本です。未ログインの記録はその端末のブラウザの中だけにあり、サイトデータの消去や機種変更で失われます。
  • ログイン中の記録はクラウド（Firestore）にあり、端末を替えてもログインすれば戻ります。中身は Firebase コンソール → Firestore Database →「データ」タブの users / 自分のuid 以下で直接確認できます。
  • 2台で同じ日を同時に編集すると、後から保存した方の内容が残ります。片方で入力を終えてからもう片方を使ってください。
  • ログイン前の端末内データは、移行後も消さずに残しています（控えとして）。
  • 無料枠の上限（1日あたり読み取り5万回・書き込み2万回）に個人利用で達することはまずありませんが、Firebase コンソールの「使用状況」で確認できます。
  • CSV などへの書き出し機能は未実装です（次版以降の候補）。
