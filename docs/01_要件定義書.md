# 筋トレメモアプリ 要件定義書

- アプリ名: **WorkOut Note**
- 版: 1.1（確定）
- 作成日: 2026-09-17
- 画面モック: `mock/mock.html`（https://claude.ai/artifact/2YtKAzJAYX7cq61nznW7fA）
- 参考: 依頼者提供の筋トレMEMOスクリーンショット3枚（ホーム／セット入力／種目履歴）。画面構成・操作感の参考とし、ロゴ・名称は使用しない
- 作成: PM／窓口担当

## 1. 目的・背景

- 「筋トレMEMO」の見た目・使いやすさは気に入っているが、広告が煩わしく課金もしたくない。
- 同等の使い勝手を持つ **広告なし・完全無料・自分専用** の筋トレ記録アプリを自作する。

## 2. 利用者・利用環境

| 項目 | 内容 |
|---|---|
| 利用者 | 本人のみ（1ユーザー） |
| 端末 | iPhone（Safari／ホーム画面に追加して利用）、PC（Chrome/Edge） |
| 主な利用シーン | ジムでiPhone片手にセット間で記録 → 家でPCから振り返り |
| 過去データ | 移行しない（新規スタート） |

## 3. 提供形態・システム構成（案）

| 項目 | 採用案 | 理由 |
|---|---|---|
| アプリ形態 | PWA（Webアプリ） | App Store配布は年99ドル必要。PWAなら無料でiPhone/PC両対応 |
| 実装 | HTML / CSS / JavaScript（ビルド不要の構成） | このPCにNode.jsが無くても開発・修正できる。長期保守が楽 |
| データ保存・同期 | Firebase Firestore（無料枠） | 端末間の自動同期、**オフライン時も記録でき電波復帰時に自動送信**（ジムの電波対策）。無料枠は個人利用なら十分 |
| ログイン | Googleアカウントでログイン（Firebase Authentication） | パスワード管理不要。本人のデータは本人しか読めないようセキュリティルールで制限 |
| 公開先 | GitHub Pages（無料・HTTPS） | gitでpushするだけで更新。PWAにはHTTPSが必須 |
| 費用 | 0円 | 全て無料枠内 |

※ Firebase／GitHub のアカウント作成とログインは **ご本人の操作** が必要です（手順書を用意します）。

## 4. 機能要件

### 4.1 画面構成（下部タブ：ホーム／履歴・分析／体組成／設定）

| # | 画面 | 概要 |
|---|---|---|
| 1 | ホーム | 上段：月カレンダー（実施日は塗り丸、選択日は白丸）＋合計負荷量（7日間・週別バー6週分／28日間／総合計、乗り物換算）＋MONTHLY ARCHIVE（当月日数・通算日数）。下段：「トレーニングを追加」「RM計算機」「過去の日からコピー」、選択日の記録一覧（種目・各セット・RM）、その日のメモ |
| 2 | 種目選択 | 部位チップ → 種目リスト（前回の日付と重量×回数を併記）。種目の新規追加 |
| 3 | セット入力 | インターバルタイマー（秒数＋START、プリセット）、Last Record（コピー／履歴）、セット行（重量±・回数±・メモ・RM自動表示・補助チェック・削除）、セット追加 |
| 4 | 種目履歴・分析 | 期間切替、推定1RM／総ボリュームのグラフ、日付ごとのカード（TOTAL・MAX 1RM・各セットRM） |
| 5 | 履歴/分析タブ | 部位別の種目一覧（最終実施日・回数・ベスト1RM）→ 種目履歴へ |
| 6 | 体組成 | 今日の体重・体脂肪率の入力、推移グラフ |
| 7 | 設定 | テーマ、部位・種目の管理、重量ステップ、タイマー初期値、同期状態、ログアウト |
| 8 | RM計算機（シート） | 重量×回数 → 推定1RMと回数別の目安重量 |

※ 筋トレMEMOにある「SNS」タブ、lbs表示は対象外（kgのみ）。

### 4.2 機能一覧

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F-01 | カレンダー表示 | 月移動、今日へ戻る、実施日のマーク（部位ごとの色ドット） | 必須 |
| F-02 | トレーニング記録 | 日付 × 種目 × セット（重量kg・回数）。セットの追加/削除/並び、種目ごとのメモ | 必須 |
| F-03 | 入力のしやすさ | 大きめのボタン、重量の±ステッパー（刻み 2.5kg／1kg 等を設定可）、数値キーパッド、前セットの値を次セットに自動引き継ぎ | 必須 |
| F-04 | 部位・種目マスタ | 初期プリセット（胸・背中・肩・腕・脚・腹・有酸素 等と代表種目）。種目の追加・名称変更・並び替え・非表示 | 必須 |
| F-05 | 前回記録の表示・コピー | セット入力画面に同種目の前回実施日と内容を表示。ワンタップで今日のセットにコピー | 必須 |
| F-06 | グラフ・推移 | 種目別：最大重量／総ボリューム（重量×回数の合計）／推定1RM。期間切替（1か月・3か月・半年・1年・全期間） | 必須 |
| F-07 | 体重・体脂肪の記録 | 日別に体重(kg)・体脂肪率(%)を記録、推移グラフ表示 | 必須 |
| F-08 | インターバルタイマー | セット記録後にワンタップで開始。残り時間表示、終了時に音＋バイブ（※iPhoneのPWAは振動API非対応のため、iPhoneは音と画面表示で通知）。秒数プリセット（60/90/120/180秒）と変更 | 必須 |
| F-09 | 自動同期 | iPhone・PC間でリアルタイム同期。オフライン記録 → 復帰時に自動同期 | 必須 |
| F-10 | 自己ベスト表示 | 種目ごとの最大重量・最大推定1RMを更新したらバッジ表示 | 次版以降 |
| F-11 | データのエクスポート | 全データをCSV／JSONでダウンロード（バックアップ用） | 次版以降 |
| F-12 | 日別記録のコピー | 過去のある日のメニュー（種目・重量・回数）を丸ごと選択日にコピー | **必須（初版）** |
| F-13 | テーマ切り替え（赤／黒） | 赤基調と黒基調（黒地＋赤アクセント）の2テーマ。ホーム右上のボタン1つで即切り替え、選択は端末に記憶 | **必須（初版）** |
| F-14 | 合計負荷量の集計 | 7日間（週別バー6週分）／28日間／総合計をトン表示。乗用車1.5t・バス15t・旅客機350t換算を併記 | 必須 |
| F-15 | MONTHLY ARCHIVE | 当月のトレーニング日数、通算トレーニング日数 | 必須 |
| F-16 | RM計算機 | 重量×回数から推定1RM、回数別の目安重量を表示 | 必須 |
| F-17 | 補助チェック・セットメモ | セットごとに「補助あり」フラグと一言メモ | 必須 |

**推定1RMの換算式**：`重量 ×（1 + 回数 ÷ 40）`（筋トレMEMOの表示値と一致することをスクリーンショットの数値で確認済み。例：35kg×15回＝48.13kg、58kg×33回＝105.85kg）

### 4.3 種目タイプ

| タイプ | 入力項目 | 例 |
|---|---|---|
| ウェイト | 重量(kg) × 回数 | ベンチプレス、スクワット |
| 自重 | 回数（加重は任意入力） | 懸垂、腕立て |
| 有酸素・時間系 | 時間(分)、距離(km)は任意 | ランニング、プランク |

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| 操作性 | スマホ片手操作前提。1セットの記録は3タップ以内を目標 |
| レスポンシブ | スマホ幅（〜430px）とPC幅の両方で崩れず使える |
| 表示速度 | 起動後すぐカレンダーが表示される（キャッシュ利用） |
| オフライン | 電波が無くても起動・記録可能 |
| セキュリティ | ログインした本人のみ自分のデータを読み書き可能（Firestoreセキュリティルール） |
| 保守性 | ビルド不要・素のJSで構成し、後から機能追加しやすいファイル分割にする |
| 広告・課金 | なし |

## 6. 対象外（今回は作らない）

- 複数ユーザー対応、SNS共有
- 既存アプリからのデータ移行
- 食事・カロリー管理
- ルーティン（メニューテンプレート）の高度な管理 ※F-12の日別コピーで代替
- Apple Watch連携、ヘルスケア連携

## 7. 体制

| 役割 | 担当内容 |
|---|---|
| PM／窓口担当 | 依頼者とのやり取り、要件定義、仕様決定、進捗・成果物の報告 |
| 開発担当 | 設計・実装 |

## 8. 進め方

1. 要件定義（本書）→ **依頼者承認**
2. 画面・データ設計（画面モックを提示 → 見た目を確認いただく）
3. 開発（まずは端末内保存で動く版 → 次にFirebase同期を接続）
4. テスト → 修正
5. 公開（GitHub Pages）→ iPhoneのホーム画面に追加
